# psyweb · Turn a PsychoPy experiment into a single web page anyone can run

**In one sentence**: take the experiment you designed in PsychoPy Builder, convert it into **one 3–4 MB `.html` file**, send it to participants over any chat app → they **double-click it on their computer** and run it → the final page hands them **a result summary + a CSV download + a data QR code**, and they send a screenshot back to you.

No server, no hosting, nothing for the participant to install, and **no data is ever uploaded**.

---

## Why this exists

It started with a very specific problem: **participants are not in the same place.**

The usual approach is to invite people into the lab. But that means they have to free up time, travel, and fit your schedule — **most people simply won't bother**. So "recruiting participants" itself becomes the most labour-intensive part of a study: who you can reach is locked to geography, sample sizes stay small, data collection is slow, and many ideas stall on "not enough people" before they even start.

This tool tries to fix both ends:

- **For participants**: nothing to install, nothing to sign up for, no trip to make. They receive a file, double-click it on a computer, and follow the prompts.
- **For researchers**: who you can reach is no longer limited by geography, so **sample size and data-collection throughput** go up. Data can come back three different ways (QR screenshot / CSV / summary screenshot) — whichever is easiest.

It also handles the two things most likely to go wrong: data **never passes through a server** (nothing is uploaded, so there is no upload-related exposure), and if a participant closes the page halfway through, the data is auto-saved and can be recovered.

In one line: **it drops the cost of "get people into the lab" down to "send one file".**

## ⚠️ First, two kinds of HTML — they are NOT the same thing

This is the single most confusing point, and the easiest way to waste an hour. Read this table before anything else:

| | **HTML exported by PsychoPy Builder** | **HTML produced by this tool** |
|---|---|---|
| What it is | A folder of files: `index.html` + `xxx.js` + `xxx-legacy-browsers.js` + `lib\` + images/condition files | **One** self-contained `.html` file |
| Can you send it to participants? | ❌ **No** | ✅ Yes |
| Why | It resolves its runtime via **relative paths** and uploads data to the **Pavlovia** server by default; there is no start page and no data exit — double-clicking it usually gives a blank page or errors | Runtime and assets are inlined; it has a start page (with informed consent) and a data exit |
| Where the data goes | Uploaded to Pavlovia (needs an account and a network) | Stays on the participant's computer; they send it back to you |
| Its role here | The **input** (an intermediate artifact) | The **final artifact** (the thing you send out) |

> In other words: **Builder's "Export HTML" is the raw material, not the product.** It has to go through this tool to become something you can send out.

## How to use it (pick one of three)

### ① Online tool (easiest, needs internet)

Open **https://yyymzzz.github.io/psyweb-toolkit/** →

1. In PsychoPy Builder, use `File → Export HTML…` (or sync to Pavlovia once) to get a folder;
2. **Drag the whole folder onto the page**;
3. Download the generated single `.html` and send it to your participants.

Everything is computed in the browser; files are not uploaded (assets load locally).

### ② Offline single-file version (unstable network / air-gapped machine)

Download the **[offline single-file version](https://yyymzzz.github.io/psyweb-toolkit/offline.html)** (~3.2 MB) and **double-click it** —
it is the inlined offline build of ①, with identical functionality. No server, no network, works on Windows / macOS / Linux.
(Source: [`site/offline.html`](site/offline.html), generated by `src/build-single-tool.ps1`.)

### ③ Local tool (the only way to consume `.psyexp` directly)

Compiling a `.psyexp` into `.js` is done by **PsychoPy itself** (a Python program). Its dependencies include
native desktop libraries such as `wx` and `pyglet`, which cannot run in a browser (measured: 158 modules in the
compile chain), so **that step cannot be moved into the web page**. If you want "drag a `.psyexp` and be done",
run the local tool on your own machine:

```powershell
git clone <this repo>; cd <this repo>
pwsh -File scripts/setup.ps1     # environment check: Node / deps / assets / PsychoPy, then prints the next command
# then double-click 启动psyweb工具.cmd (requires Node.js installed locally)
```

The local tool **calls the PsychoPy you already have** to compile the `.psyexp`, then goes through exactly the same packing pipeline as the web version.

## How the data comes back (three channels, pick any)

After finishing, the participant sees a results page with three exits:

| Channel | Use it for | Note |
|---|---|---|
| **Data QR code** | Fastest. The participant screenshots the QR codes and sends them to you | In WeChat, they **must** tick "original image", otherwise compression destroys the code |
| **CSV download** | Most robust. One click produces `psyweb_'01'.csv` | Best when file transfer is easy |
| **Summary screenshot** | Fallback. Shows participant ID / row count / column count | For reconciliation only, not usable as data |

The experimenter drags the QR screenshots into [`collector.html`](https://yyymzzz.github.io/psyweb-toolkit/collector.html)
(or downloads it and double-clicks it — fully local) → it decodes and groups automatically → **export a merged CSV** in one click.
Screenshots from multiple participants can be dropped in together; they are grouped by dataset and never mixed up.
A message like "缺 2" means the participant missed frame 2 — ask them to resend it.

## Limits (please tell your collaborators honestly)

- **Timing precision**: `requestAnimationFrame` + `performance.now()`, with typical cross-device jitter of **5–20 ms**. It is **not comparable to a lab photodiode / EEG trigger**. Do not move paradigms that need millisecond-level rigour online.
- **Hardware**: EEG, eye tracking, serial/parallel port triggers, response boxes — none of these are available online.
- **Device differences**: screen size, refresh rate and OS are recorded in the data (`frameRate`, `OS` columns) and should be checked as covariates during analysis.
- **Ethics**: the informed-consent text is a template; **ethics review and data custody remain the researcher's responsibility** — this tool does not do that for you.
- **Browser**: a recent Chrome / Edge is required (WebGL). Phones and tablets cannot complete the experiment.
- **The file-manipulation commands in this repo** (`.cmd` / `.ps1`) are **Windows-only**; the web version and the offline single-file version are cross-platform.

## Known pitfalls (all now blocked by build-time gates)

- **ES `import` left in the exported JS**: the official legacy build may still contain ES `import`, which the browser refuses → inlined by `js-codeblock-fix.js`.
- **`Math.random.random()`**: a translation defect in the official export → fixed by the same pass.
- **Undeclared resources**: images/condition files not listed in the `.psyexp` resources are missing from the export → the packer scans condition-file contents backwards for filenames and registers them.
- **Inlining the packer into its own HTML page**: `pack-core.js` contains a **literal `</script>`** (it assembles the output HTML),
  so inlining it verbatim lets the HTML tokenizer close the tag early and the page throws `SyntaxError: Invalid or unexpected token`.
  Fix: only `</` and `<!--` are replaced with **value-equivalent** JS escapes (`<\/`, `\x3C!--`), and
  `src/verify-single-tool.js` byte-compares every inlined asset and force-parses every script block — no gate, no build.
